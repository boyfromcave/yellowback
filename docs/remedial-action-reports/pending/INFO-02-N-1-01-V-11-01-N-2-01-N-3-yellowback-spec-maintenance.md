## 1. Finding

Four places where the normative text and the shipped code disagree or where the text is silent on a rule the code enforces; none changes behaviour, all would mislead the review gate and later auditors, who are told the spec is normative:

- **02/N-1.** Quantum spec R-A2 says `pqFalconHeight` is "`NO_ACTIVATION_HEIGHT` on mainnet/testnet". Both lines set `0` on mainnet and testnet (Falcon and TOK-PQ live from the vault activation block) by the owner's final ruling D-Q-2 (2026-10-10, "Falcon from day one"). The code is right; the spec is stale on a consensus parameter.
- **01/V-11.** Upgrade plan §15.4 says "a template-output index is **not** needed (V/I parse from the coin)" — it became consensus input: I-2 (cancel) reads the intent's height and the start-up replay (`CoinsFromUndo`) gets it from that index. §15.5's act table lacks the rules decided 2026-10-11 and implemented: self-`SET_REMOVE` without burn, the slash of a REMOVED member's bond during its exit delay, displacement (D-Q-29, `Displace` hook), the bond exit delay (`exitHeight + maturity`, `bad-vault-bond-locked`), and `MIN_SET_MATURITY` (D-Q-31); its bond rule "spending the bond of an ACTIVE member sets WITHDRAWN" describes a spend the code refuses (the WITHDRAWN transition is unreachable in practice); the per-member/bond field list lacks `exitHeight`.
- **01/N-2.** "Released" (dormant, wound down past `windDownHeight + livenessWindow`, or unknown) opens the owner's selector-3 branch but closes nothing on the set's side: `CheckSetSigs` consults only currency, so current members of a wound-down set can still UNLOCK vaults and CANCEL intents. Probably intended (a set winding down should serve its users) but §15.4 should say so; an owner reading "released" may assume exclusivity.
- **01/N-3.** An UNLOCK adds `Σ I` to `epochUsed`; a CANCEL re-locks the value through V-1 (`lockedValue` grows) but `epochUsed` keeps the unlock, so a set whose unlocks are repeatedly cancelled (YED's shape: anyone may APP-spend, a wrong-price claim stream) consumes its own rate budget without value leaving. Conservative (can only refuse unlocks) and deterministic; §15.6 S-3 should state it and `yb-calibration` should size `rateLimitBps` with cancelled claims counted.
