## 1. Finding

`pq_vectors.json` (the OP_CHECKPQSIG golden: keys, signatures and two full signed spends) is regenerated by the C++ code it checks, so on its own it is self-referential. What anchors it is an *independent* implementation: `qa/rpc-tests/test_framework/pq.py`, a pure-Python SLH-DSA signer/verifier and Falcon verifier. `test_pq.py`'s `GoldenVectors` class replays the JSON through it, and the CI `python` job runs `test_pq`. Two paths turn that anchor into a silent pass:

1. The CI step starts with `if [ ! -f qa/rpc-tests/test_framework/test_pq.py ]; then echo "no PQ framework on this line"; exit 0; fi`. A rename, a move or an accidental deletion of `test_pq.py` makes the whole PQ-model step green: pyflakes, the Falcon-signer probe, `gen_pq_wallet_vectors.py --check` and the unittest run are all skipped.
2. `GoldenVectors` is decorated `@unittest.skipUnless(os.path.exists(GOLDEN), 'src/test/data/pq_vectors.json not on this branch yet')`. If the vector file moves (renamed, or relocated by a refactor of `src/test/data`), the cross-implementation replay is *skipped*. `python3 -m unittest` exits 0 with `OK (skipped=N)`, which CI accepts.

Both guards date from when the PQ framework existed on only some branches. On `upgrade/vault` both files ship on both lines, so an absence there is always a defect. ycash-dd's vault-framework step has the same `exit 0` shape (`test_vault.py`), and ycash6 has one for `test_yellowback_attest.py`. The Falcon-signer skip is already refused (04/F-1, done). Low (test fidelity).

## 3. Fix options considered

1. **Make the absences fatal unconditionally** (the audit's first suggestion). That is right for `upgrade/vault`. The same workflow text is carried on the record and fallback branches (`harden/yellowback`, `feature/yellowback-price-attest`), where these files legitimately do not exist, though fixes flow `harden` → `upgrade`, never back. Acceptable, but option 2 costs nothing more and keeps the file portable.
2. **Tie the skip to an explicit line marker instead of the file's presence** (the audit's second suggestion). On the upgrade line (`src/vault/` present) a missing file is `exit 1`. On a line without `src/vault/` the message and `exit 0` stay. **Recommended.**
3. **For the decorator: drop `skipUnless(os.path.exists(GOLDEN))`.** `setUpClass` opens the file, so a missing file is an *error*, which unittest reports as a failure. Recommended. In addition, **refuse any skip** in the PQ and vault model runs: wrap the unittest invocation so `OK (skipped=N)` with N > 0 fails, except for named, intended skips (none remain on the upgrade line once the signer probe passes).

## 4. Recommended fix

Both lines.

1. **`test_pq.py:243`** (identical on both lines): delete the `@unittest.skipUnless(os.path.exists(GOLDEN), …)` line. In `GoldenVectors.setUpClass`, keep `cls.data = _load(GOLDEN)`. If you want a clearer message than `FileNotFoundError`, precede it with `if not os.path.exists(GOLDEN): raise AssertionError('src/test/data/pq_vectors.json is missing: the cross-implementation golden replay cannot run (audit W3-PQ-5)')`. Leave the Falcon-signer `skipUnless` at `:141` as it is (CI probes the signer first) but see step 3.
2. **The workflow guards** (dd `:675`, `:684`; ycash6 `:1112-1115`, `:1149`) become line-aware:
   ```bash
   if [ ! -f qa/rpc-tests/test_framework/test_pq.py ]; then
     if [ -d src/vault ]; then echo "::error::test_pq.py is missing on the upgrade line (audit W3-PQ-5)"; exit 1; fi
     echo "no PQ framework on this line (no src/vault: not the upgrade line)"; exit 0
   fi
   ```
   Apply the same shape to `test_vault.py` (dd `:675`) and `test_yellowback_attest.py` (ycash6 `:1112-1115`). For the last one, the "not present yet (Phase A0…)" text is obsolete since the file exists on both lines: make its absence fatal on the upgrade line.
3. **Refuse unintended skips in the model runs.** Add `qa/rpc-tests/test_framework/run_unittest_noskip.py` (new, ~25 lines, byte-identical on both lines; add it to the MEDIUM-W3-P-2 manifest). It runs `unittest.main(module=None, argv=[…], exit=False)` and then fails, listing the skipped tests and reasons, if `result.skipped` is non-empty. Use it in place of `python3 -m unittest` for `test_framework.test_pq` and `test_framework.test_vault` (dd `:678, :691`; ycash6 `:1143, :1156`), and for the attest/model/util suites (dd `:660`, ycash6 `:1121`). The Falcon-signer cases would skip only without a compiler, and the probe already fails the step first. With the wrapper, they become a second line of defence.
4. **`qa/yellowback-audit.sh` (dd) `leg_ci_guards` / `leg_skip_scripts`** (`:222-251`): add a check that the workflow contains no `exit 0` after a `[ ! -f qa/rpc-tests/test_framework/…` test unless the same block tests `-d src/vault`. Make it report-only first, then blocking once this fix lands. ycash6 has no such leg; its workflow is checked by the review of this PR.
5. **Docs:** `doc/yellowback-testing.md` (both lines), in the "fail, never skip" section from 04/F-1: one paragraph naming the model-test rule. A missing framework file is fatal on the upgrade line, and a skipped Python unit test fails CI (the wrapper).
