## 1. Finding

**Mempool order (W3-N-4).** In `AcceptToMemoryPool` (`ycash-dd/src/main.cpp`) the order is: `CheckTransaction`/`ContextualCheckTransaction` → `IsStandardTx` (`:1717`) → inputs exist (`view.HaveCoins`) → BIP68 (`:1797-1801`) → **`vault::CheckTx` at `DoS(0)` (`:1803-1813`)** → `AreInputsStandard` (`:1822`) → sigops (`:1829-1836`) → fees (`:1839-1880`) → free-relay limiter → absurd fee (`:1911`) → the isolated template-input check (`:1921-1954`) → `ContextualCheckInputs` (`:1956`). `CheckTx` → `ApplyTxInner` → `ApplyAct` (`src/vault/state.cpp:667-700`) recovers **every** act signature (`:676-682`) before any membership or count check (`cosigners` `:685-697`; per-type counts `:723`, `:725`, `:727`, `:796`, `:821`, `:830`, `:876`). The inputs need only exist (anyone's coins), no fee is checked yet, and a failure scores 0, so an unauthenticated peer gets ~17 ECDSA recoveries (≈ 0.7 ms at the verifier's 39 µs) per ~1.3 KB transaction under standardness (`MAX_VAULT_ACT_BYTES = 1200`, `src/policy/policy.h:36`, enforced first in `IsStandardTx`, `policy.cpp:126-128`), changing one byte per attempt to evade `recentRejects`. It contradicts the fork's own placement of the isolated template check after fees, chosen precisely so a template failure costs "at most k recoveries, k−1 over signatures the sender must produce" (`main.cpp:1925-1934`, audit 07/F-1). Stock Ycash's comparably heavy pre-fee work (Sapling proofs, JoinSplit signatures in `ContextualCheckTransaction`) scores DoS 100.

**Unbounded act signatures (W3-V-2).** `DecodeAct` (`src/vault/act.cpp:291-310`) accepts any number of trailing 65-byte pushes as `S_1..S_n` (`while (pc < spk.end())`, `:300-305`); `ActFieldsValid` (`:150-172`) checks headers, not counts. With standardness off (`-acceptnonstdtxn`, regtest/devnet or a misconfigured node) and in **blocks**, an act is bounded only by `MAX_TX_SIZE_AFTER_SAPLING = 2,000,000` → ≈ 30,000 recoveries ≈ 1.2 s single-core per invalid act (`ApplyBlock` is sequential), before the block is found invalid. Both lines identical (`src/vault/*` byte-identical; `ycash6/src/main.cpp:2050-2058` has `CheckTx` at `DoS(0)` before `AreInputsStandard` at `:2075`). 01/N-1 (valid-block cost of `OP_CHECKSETSIG`) is the per-block budget question and is handled in `LOW-W3-V-4-V-6-01-N-1-ycash-per-block-validation-cost.md`; this report only removes the *invalid*-act amplification.

## 2. Root cause

- `src/main.cpp:1803-1813` (ycash6 `:2050-2058`) — `vault::CheckTx` placed before `AreInputsStandard`, sigops and fees; `return state.DoS(0, …)` for every reason.
- `src/vault/act.cpp:300-305` — no bound on `a.sigs.size()`.
- `src/vault/state.cpp:678-682` — recovery loop runs before every count check; the expected count is knowable first: CREATE 0 (`:673`, `:702`), EQUIVOCATION 0 (`:847`), HEARTBEAT 1 (`:796`), JOIN 1 / 2 / `1 + slashThreshold` by the set's state (`:722-727`), REMOVE 1 (voluntary exit) or `slashThreshold` (`:821`, `:829-830`), WINDDOWN `slashThreshold` (`:876`).

## 3. Fix options considered

1. **(a) Reorder in ATMP + (b) a decode bound + (c) count-before-recover (recommended, all three).** (a) is local mempool policy; (b) and (c) live in consensus files but — see below — change **no** valid/invalid outcome.
2. **Move `CheckTx` after `ContextualCheckInputs`.** Would require valid signatures on the non-template inputs (an owned coin) before any recovery. Rejected: a state-rule failure would then first pay full script verification (PQ owner spends ≤ 9 KB SLH-DSA, the template's set signatures), the same order of cost the move saves; and the isolated template check already sits after fees by design. Option (a)'s placement plus (b)/(c) bounds the residual to ≤ 16 recoveries per attempt.
3. **Raise every act failure to DoS 100.** Rejected: tip-dependent reasons (membership, maturity, set existence, rate) are no proof of misbehaviour (the 07/F-1 rule), and see §7 on pre-upgrade peers.
4. **Policy-only bound (rely on `MAX_VAULT_ACT_BYTES`).** Leaves the block path and `-acceptnonstdtxn` unbounded. Rejected as sufficient; kept as is.

**Is (b)/(c) a consensus change?** It lives in `src/vault/` (review gate) but is **validity-neutral**: every act type already demands an exact signature count (above), and the largest legitimate count is a closed `SET_JOIN` with `1 + slashThreshold ≤ 1 + seats ≤ 1 + MAX_SET_SEATS = 16` (`act.h:50`, `SetCreateBody::Valid` `act.cpp:127-131`). So an act with more than 16 signatures is invalid today and stays invalid; an act whose count mismatches its type/state is invalid today and stays invalid. What changes is (i) the **cost** of finding that out and (ii) the **reject reason** for some invalid acts (`bad-vault-act-sig` "unrecoverable" vs `bad-vault-act-sigs` "count" when both apply). Reject reasons are not consensus, but they are pinned by the Python model and the functional harness (`vault_harness.py:233` requires node and model reasons), so the model changes in the same commit.

**Rule-4 four-part check (PR body).** DigiByte does **X** = nothing equivalent: DigiDollar has no OP_RETURN act carrying a variable list of recoverable signatures (its oracle/MuSig2 bundles are a different mechanism and are not ported, `docs/mapping.md` row "Oracle / MuSig2"); in **Y** = `ref/digibyte/src/oracle/` using **M** = Schnorr/MuSig2 aggregate verification. (`ref/` was not checked out where this report was written; the reviewer re-greps it.) The Ycash equivalent **Z** = the vault primitive's `YV` act (`src/vault/act.cpp`, plan §15.5), which lacks **M** and verifies by per-signature ECDSA public-key recovery. So the adaptation **W** = a decode-time bound `MAX_ACT_SIGS = 1 + MAX_SET_SEATS` (16) on `S_1..S_n`, and in `ApplyAct` the per-type expected count compared before the first `RecoverSig`; validity unchanged.
**In-tier ladder answer.** Tier 3 stands (Vault is unreleased; no activation height on any public network). Rung: **the existing act's decoder and rule function** — no new opcode, no template change, no transaction field, no new state. A cheaper rung (policy only) leaves blocks and non-standard relays unbounded; nothing above it is needed.

## 4. Recommended fix

1. **Decode bound (consensus file, both lines).** `src/vault/act.h`: `static const unsigned int MAX_ACT_SIGS = 1 + MAX_SET_SEATS; //!< a closed SET_JOIN: the joiner + slashThreshold <= seats cosigners`. `src/vault/act.cpp` `DecodeAct` (`:300-305`): inside the loop, before `push_back`, `if (a.sigs.size() >= MAX_ACT_SIGS) return std::string("bad-vault-act-sigs");` (so at most 16 pushes are ever parsed). Keep the canonical re-encode check (`:307`).
2. **Count before recover (consensus file, both lines).** In `VaultState::ApplyAct` (`state.cpp:667-700`), after `ActFieldsValid` and before the recovery loop, compute `std::optional<size_t> expected` per type from the state the type's case reads anyway (`GetSet` once; for JOIN `IsOpen()` → 1, `CountCurrent(...) >= slashThreshold` → `1 + slashThreshold`, else 2; HEARTBEAT 1; REMOVE: `act.sigs.size() == 1 && burn == 0` → 1 (the voluntary-exit shape; its signer is checked after recovery), else `slashThreshold`; WINDDOWN `slashThreshold`; CREATE/EQUIVOCATION 0 — already refused at `:673`, `:847`); an unknown set → return the type's existing "noset" reason first. `if (act.sigs.size() != *expected) return std::string("bad-vault-act-sigs");` Then recover as today. Do **not** restructure the per-type cases beyond this pre-check (rule 7: no tidying); the existing post-recovery checks stay as the authoritative ones.
3. **ATMP order (both lines).** Split the block at `main.cpp:1803-1813` (ycash6 `:2050-2058`): keep `vaultSnapshot = vault::TipSnapshot()` where it is (`AreInputsStandard` at `:1822` and `ContextualCheckInputs` take it); move the `vault::ViewCoinAccessor` + `vault::CheckTx` call to just before the isolated template check (`:1921`, after the absurd-fee check `:1911-1917`; ycash6 just before `:2210`). Nothing between depends on its verdict. The accessor reads only the transaction's own prevouts (`state.cpp:465`), which `HaveInputs`/`GetValueIn` have cached in `view` before `view.SetBackend(dummy)` (`:1819`), so it works unchanged after the move — verify with the existing `vault_policy_tests.cpp` mempool cases.
4. **DoS scoring (both lines; conservative).** Keep `DoS(0)` for every tip-dependent reason. For the byte-level reasons that no honest relay can produce — `bad-vault-act-malformed`, `-params`, `-type`, `-multi`, `-coinbase`, `-novin`, `-sig` (unrecoverable), `-sigs` raised by the new decode bound, `bad-txns-vault-malformed` (a MALFORMED template output) — return `DoS(10)` (the stock `old-consensus-branch-id` level, never 100) **only when the act output is longer than `MAX_OP_RETURN_RELAY` (83 bytes, `script/standard.h:66`)**: a pre-upgrade node relays a ≤ 83-byte `YV…` memo as ordinary data and, because activation disconnects no pre-upgrade peer today (W3-P-1), must not be penalised for it. Implement as a small classifier `vault::IsByteLevelActFailure(reason)` in `src/vault/node.cpp` used by ATMP. Revisit (raise to unconditional 10) when W3-P-1's protocol-version gating lands. **The CI DoS gates must change in the same PR, or it goes red:** both lines enforce U-21 ("every fork-inserted `DoS(` in a mempool path is `DoS(0)`") — ycash-dd in `qa/yellowback-audit.sh` `leg_dos_upgrade` (`:272-340`; the `MEMPOOL = {"AcceptToMemoryPool"}` set `:284`, its rule `:323-324`), ycash6 in `.github/workflows/yellowback-tests.yml:911-924` (the `grep -v … | { ! grep -v 'DoS(0'; }` allowlist, extended by `0742e43` with a clause that a `DoS(` split over lines must take a stock `dosLevel…` argument). Add one allowlisted shape for the classifier-gated level (e.g. `DoS(vault::IsByteLevelActFailure(*vaultBad, tx) ? 10 : 0, …` on one line, so ycash6's split-call clause does not fire) to both gates, and amend U-21's text in the upgrade plan; two reviewers see the gate change with the code.
5. **Model.** `qa/rpc-tests/test_framework/vault.py`: `parse_act_script` (`:1133-1152`) refuses more than 16 signatures with `bad-vault-act-sigs`; `_apply_act` (`:1937+`) compares counts before `recover_compact`. Align the model's reason strings with the node's for these cases.
6. **Spec.** Plan §15.5 (lines 937-942): "`n ≤ 16` (`1 + MAX_SET_SEATS`); more is `bad-vault-act-sigs`, refused before any signature is recovered; each act type's signature count is compared before recovery". §15.6 / mempool notes: "acts and template rules are checked after the fee checks". `doc/yellowback-pq-dos.md` §3: the act path's bound (≤ 16 recoveries per relayed transaction, scored 0/10). `docs/mapping.md` §22 row ("act signatures: count before recover; why not a policy bound only").

## 5. Tests

- **Unit `src/test/vault_act_tests.cpp` (both lines):** `decode_rejects` gains: an act with 16 signatures decodes; with 17 → `bad-vault-act-sigs`; with 30,000 → `bad-vault-act-sigs` and the decoder stops at 17 (assert via a counting `CScript` iterator or simply a time bound ≤ 10 ms).
- **Unit `src/test/vault_state_tests.cpp`:** for each act type, an act with the wrong count (one more / one fewer, all signatures valid recoverable) → `bad-vault-act-sigs` **with zero `RecoverSig` calls** — add a test-only recovery counter in `vault/act.cpp` (`#ifdef` or a `std::atomic` read by tests, as other test hooks in the tree) — this is the test that would have caught W3-V-2; the positive cases unchanged; the existing negatives that expect `bad-vault-act-sig` for an unrecoverable signature with the right count still do.
- **Unit `src/test/vault_policy_tests.cpp`:** ATMP order: a transaction with a 16-signature garbage act and insufficient fee is refused `insufficient fee` (fee check first) with zero recoveries; with enough fee, `bad-vault-act-sigs`/`-sig` at the expected DoS score (0 for ≤ 83-byte acts, 10 above).
- **Functional `qa/rpc-tests/vault_dos.py` (both lines):** the mininode peer relays (i) an act with garbage signatures and a valid fee → rejected, peer score 10, not banned after one; (ii) a ≤ 83-byte malformed `YV` memo → rejected, score 0; (iii) a node with `-acceptnonstdtxn=1` refuses a 1,000-signature act quickly with `bad-vault-act-sigs`.
- **Golden / vectors:** `vault_vectors.json` acts carry ≤ 16 signatures — regenerate nothing unless a vector pins a reject reason (grep `bad-vault-act` in the generator); `yellowback` golden unaffected (no act count change); the C++/Python model parity suite (`test_vault.py`, `vault_primitive.py`'s model check) passes.

## 6. Acceptance criteria

- No path (block, mempool, `-acceptnonstdtxn`) recovers more than 16 act signatures for one act, and none recovers any when the count is wrong for the type and state.
- In ATMP, `vault::CheckTx` runs after `AreInputsStandard`, the sigop budget, the fee and the free-relay checks on both lines; byte-level act failures above 83 bytes score 10, everything else 0.
- PR body carries the four-part check, the ladder answer and the validity-neutrality argument; two independent reviewers (`src/vault/`, `src/main.cpp` are gated).
- Spec §15.5 states the bound.

## 7. Risks and side effects

- **Chain split:** none expected (validity-neutral), but treat as consensus: land on both lines together, before P8 freezes the vectors and the spec. A reviewer must confirm the per-type expected counts match the post-recovery checks exactly (a mismatch *would* change validity).
- **Peer scoring:** DoS 10 for > 83-byte byte-level failures can, in principle, score an upgraded peer that relays a transaction mined-invalid by a future rule change; 10 per transaction, ban at 100. Keep the classifier list short and byte-level only.
- **Free-relay limiter:** after the move, a vault-invalid free transaction consumes `dFreeCount` before it is refused — the same as any stock transaction that fails in `ContextualCheckInputs`. Accepted.
