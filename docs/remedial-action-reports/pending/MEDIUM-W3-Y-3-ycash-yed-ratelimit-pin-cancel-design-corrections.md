## 1. Finding

**R-1d (consensus, the code part of W3-Y-3).** The primitive's S-3 adds every APP/UNLOCK spend's `Σ I` to the set's `epochUsed` and never subtracts it on a cancel (`src/vault/state.cpp:524-529`); that is deliberate and recorded (spec S-3 note, audit 01/N-3). The YED module adopts an attestor set only with pinned seats, thresholds, maturity and liveness window — **but not `rateLimitBps`** (`src/yellowback/module.cpp:41-50`; mirror `src/yellowback/state.cpp:1036-1042`). A YED set created with a non-zero rate limit is adopted, and then a single griefer's claim-and-cancel loop (each round a consensus-valid claim of an underwater vault, cancelled by a colluding seat) spends the set's epoch budget, and **other vaults' honest claims are refused with `bad-txns-vault-rate` exactly when liquidations matter**. The owner's decision 7 (design `:25`) left S-3 alone and asked to "size `rateLimitBps` with it in mind"; nothing in consensus or the release process enforces a value, and for YED any non-zero limit is a liquidation throttle that the claimant cannot route around.

**Design-document errors (W3-Y-3 items 1, 3, 5, 6; NEW-2; NEW-3).** (i) C5's "or once `CANCEL_QUIET` blocks have passed since the cancel and the position is not CLAIMING" (`yellowback-cancel-limit-design.md:180-181`) releases the path-(b) residual after 7 days while the hollowed vault is still open; its supporting argument ("a later honest claim liquidates the vault within one round", `:186-187`) fails because the re-created vault is at ≤ 100 % at `pClaim` and no claimant burns D for ≤ D. (ii) R-1c's "roughly 5 % of D" (`:63-71`) is wrong: path (b) is reachable only above a 1.1905× attestor/pool spread and the residual is then ≥ 20 % of the collateral; the owner approved C5's bound on the understated number. (iii) A-8's "No path lets an owner avoid the early-redeem fee through a self-claim plus cancel" (`:245-246`) is true only of the cancel variant; a plain self-claim avoids it (W3-Y-7). (iv) The co-signer membership "in the block's set snapshot" (`:124-125`) does not say what happens to a member evicted, exited or ejected earlier in the same block, or joined in it. (v) C4b is counted in the summary table as if it bounded the lone seat (`:201`); it is a deterrent only (its own `:174-175`). (vi) The quiet-reset counter must stay per vault (the stronger choice) — the text should say so explicitly so an implementer does not key it per member. **NEW-2:** on path (b) a third-party claimant burns D plus FEE-1′ and may take at most `D·COIN/pClaim` zat — worth D at `pClaim` and ≤ 0.84·D at `pEmerg` — so path (b) never pays an outsider; it is a self-claim/extraction path only, including in the "attestor set colludes high" row it was designed for (`yellowback-v3-development-plan.md:1499`). The upgrade plan repeats (ii) in U-24 "given up (iv)" (`yellowback-upgrade-plan.md:1288`, "≈ 5 % of the debt").

## 3. Fix options considered

| | A — **pin `rateLimitBps == 0` for the YED set** (module adoption rule) | B — release-checklist value only (no consensus) | C — primitive: refund `epochUsed` on a cancel | D — exempt YED (module-governed tags) from S-3 |
|---|---|---|---|---|
| Effect | A YED set with any rate limit is not adopted (the module then has no attestor set: mints refuse, as for any wrong shape). Claims are never rate-refused. | Relies on the creator; a mistake is permanent (set params are immutable). | Removes R-1d for every set. | As A for YED. |
| Footprint | One clause in two places (`AdoptedSet`, mirror), model mirror; no hash change (every fixture uses 0). | None. | Primitive consensus change, `vault_vectors.json` regenerates, Hawkeye/YEW copies re-pin; changes the bridge's semantics. | Primitive change. |
| Verdict | **Recommended.** Follows the 03/I-3 precedent (thresholds pinned the same way). | Rejected: unenforced. | Rejected: primitive change for a module concern; the bridge wants the conservative S-3. | Rejected: primitive change. |

What A gives up: a set-wide cap on how fast YED collateral can leave through claims. For YED that cap is undesirable — the module's own bound on bad debt (D-IT-13) assumes liquidations proceed; outflow is already bounded per vault by RED-4/RED-5 and by `CLAIM_DELAY`. This revises owner decision 7 (design `:25`) from "size it" to "pin it to 0"; record it as a decision.

**Rule-4 four-part check (PR body).** DigiByte does **X** = liquidate without any global throughput cap, in **Y** = `ref/digibyte/src/digidollar/`, using **M** = per-position validity only. The Ycash equivalent **Z** = the vault primitive's S-3 set-wide epoch rate limit (`vault/state.cpp:524-529`), which a set's creator may switch on and which no cancel refunds, so it can throttle liquidations set-wide. So the adaptation **W** = the module adopts the attestor set only with `rateLimitBps = 0`, beside the thresholds it already pins.
**In-tier ladder.** A **module adoption rule** (no primitive change; per-set parameter already in state), the lowest consensus rung; the cheaper non-consensus rung (B) cannot bind an immutable set created wrongly.
