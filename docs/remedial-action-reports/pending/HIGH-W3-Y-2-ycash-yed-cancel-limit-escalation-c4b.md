## 1. Finding

Any single ACTIVE member of the 15-seat OPEN YED attestor set can spend a claimant intent back into its vault with one set signature (`<cancelSetId> OP_2 OP_CHECKSETSIG`, `cancelThreshold` pinned to 1). After CAN-1 the cancel is value-neutral for the claimant's YED, but nothing limits how often it happens: the module keeps no per-vault memory of cancels, the member cannot be voted out (the module refuses `SET_REMOVE`/`SET_WINDDOWN` of the attestor set, D-Q-29), EQV-1 never fires on a cancel, and the only involuntary exit (bond-weight displacement) returns the bond and can be answered by re-joining larger. Each round costs the canceller a signature, a network fee and a 10,000-zat refund carrier; it costs the claimant FEE-1′ (≥ $1, half to an attestor when armed), network fees and 12 h — a rational claimant stops after one or two rounds.

So one seat — the vault owner's own (R-1a), a bribed one ("cancel as a service") or a stolen key (R-1b) — keeps every claim on one vault, or on every vault at once in a crash, from ever releasing while the collateral falls through 125 % and 100 %; YED holders carry the bad debt. D-IT-13's calibration prices 12 h of delay at 2.1 % worst-year bad debt and 24 h at 3.2 %; an unbounded veto removes the bound. Combined with HIGH-W3-03-NEW-1 the same seat also protects a hollowed vault from later claims. The owner accepted this for "this release" on 2026-10-13 pending the cancel-limit design; the wave-3 auditor recommends the release gate treat it as **blocking**, and this report asks the owner to adopt that.

## 3. Fix options considered

The design doc (`yellowback-cancel-limit-design.md` §2-§3) evaluated C0 (raise the threshold), C1 (per-vault budget), C2 (escalating co-signed cancels), C3 (canceller pays the claimant's fees), C4a/C4b (slash a wrong cancel) and C5 (residual hold). The owner approved **C2 + C5 + C4b** on 2026-10-13 (`:13-30`). This report implements **C2 (CAN-2) + C4b**; C5 (CAN-3), corrected to hold until the position closes, is in `HIGH-W3-03-NEW-1-ycash-yed-residual-role-floor-emergency-sizing-hold.md` because it is the same code as the residual rules and must land with them.

| | **C2 + C4b (approved; recommended)** | C0 `cancelThreshold` 2 | Smaller bounded deterrent: C2 without C4b |
|---|---|---|---|
| Lone seat (R-1a/b) | one 12 h round per vault per `CANCEL_QUIET`; a false price statement is slashable when the seat also attested at R | powerless alone; two seats block forever | one round per quiet period, no penalty |
| Sustained wrong-price campaign | stoppable while ≥ 5 honest members are live within 12 h; never exhausted | 2 per round | as C2 |
| Footprint | 2 `VaultRecord` fields + 2 `IntentRecord` fields, one payload type, one EQV-1 evidence variant | one constant | 2 `VaultRecord` fields, one payload type |
| Verdict | **Recommended** (owner-approved) | Rejected by the owner (Q3): gives up "one honest watcher stops the theft" for every claim | Acceptable fallback if C4b slips: the bound comes from C2 alone (C4b is a deterrent, not a bound — W3-Y-3 item 5); ship C4b as the next commit, not "phase 2" indefinitely |

C1 is rejected (exhaustible: a thief burns N cancels with wrong-price claims, then the N+1-th stands); C3 inverts the brake (honest cancellers pay the thief); C4a's proof reads the very prices a wrong-price attack falsifies.

**Rule-4 four-part check (PR body).** DigiByte does **X** = make a DigiDollar liquidation final at inclusion, in **Y** = `ref/digibyte/src/digidollar/`, using **M** = no challenge window (DigiDollar has no veto, so no veto needs bounding). The Ycash equivalent **Z** = the primitive's I-2 cancel with a set-level `cancelThreshold` (`vault/state.cpp:544-551`, upgrade plan §3.4), which has no memory across rounds and so no per-vault limit, and lacks **M**. So the adaptation **W** = a module rule that remembers per vault how many cancels the position had within `CANCEL_QUIET` and requires that many plus one distinct current members (capped at `CANCEL_SIGNERS_MAX`) to co-sign the next cancel, each co-signer putting on record a price at the claim's reference height that says "not claimable" — a statement EQV-1 can slash when it contradicts the member's own attestation.
**In-tier ladder.** Tier 3 decided. A **module** rule (the limit is YED-specific; bridge cancels unaffected), on the **existing** intent cancel branch (no opcode, no template, no transaction field), with an **existing carrier** shape for the payload, **per-vault** state (two `VaultRecord` fields; two `IntentRecord` fields recording the claim's reference height and path), no global table. A cheaper rung does not work: a wallet/agent policy cannot bind a hostile canceller, and C0 (one constant) gives up the single-watcher response for every claim.

## 4. Recommended fix

Parameters (consensus constants beside `ATTESTOR_SEATS`, following the 03/I-3 precedent: not in `ParamsRecord`, not hashed): `CANCEL_SIGNERS_MAX` = 5 (regtest 3); `CANCEL_QUIET` = 8,064 blocks (regtest 40); `CANCEL_COSIGN_MAX` = 7 entries (the 520-byte carrier push, §4 step 2); schedule `required = min(q + 1, CANCEL_SIGNERS_MAX)` = 1, 2, 3, 4, 5, 5, …

1. **State** (`view.h`, appended **last**, SERIALISATION.md §1): `VaultRecord` += `uint8_t cancelCount`, `int32_t lastCancelHeight` (0 at the mint; the cancel's `v = vault.value()` copy carries them to the re-created position, so the counter is **per position**, not per member — W3-Y-3 item 6: keep it per vault). `IntentRecord` (claimant only) += `int32_t claimRef` (the claim payload's `refHeight`) and `uint8_t claimPath` (`'a'`/`'b'`), written in `ApplyVaultSpend` at `:784-795` from `p.refHeight` and `facts.claimPath`. `SCHEMA_VERSION` → 14 (shared with HIGH-W3-03-NEW-1 if they land together, else 15).
2. **Payload CANCEL_COSIGN** (`payload.h:63-71`: next free type **0x09**; 0x04 and 0x10-0x1F stay reserved per `payload.h:39-40`). OP_RETURN body: `type 0x09 | version 0x03` and nothing else — **no count and no hash in the outputs**, so the entries can be topped up after the set signature (see "Why the entries live outside the outputs" below). Entries ride in **one** W2 SCRIPTSIG carrier input (`script.h:143-168` `CarrierScript`/`ParseCarrierScriptSig`, hash-committed in its redeem script) under a new magic **`"YC"`** | version 1 | count u8 | count × entry, `entry = seq u16 | priceMicroUsd u32 | sig65` (71 bytes; 7 entries = 501 bytes ≤ 520). Under `BundleCarrier::OP_RETURN` regtest mode, the same blob may ride in the payload tail, as bundles do. `DecodeCancelCosign` in `payload.cpp`/`bundle.cpp`; a malformed blob, `count == 0`, `count > CANCEL_COSIGN_MAX` or trailing bytes → `intent-cancel-cosign`.
3. **The signed message** (`attest.h`, beside `AttestMessage` `:45`): `CancelStatementMessage = SHA256d("YedCancelStatement" ‖ attestorSetId(32) ‖ intentOutpoint(36) ‖ seq u16 ‖ priceMicroUsd u32 ‖ citedHeight u32 ‖ blockHash(citedHeight)(32))`, with `citedHeight = claimRef`. One 65-byte low-S recoverable signature per entry is both the co-signature (it binds the intent outpoint, so a statement cannot be replayed onto another claim; a published regular attestation cannot be used as consent) and the C4b price statement.
4. **The rule (CAN-2 + C4b)** in `ApplyIntentSpend`'s cancel branch, after the CAN-1 refund checks (`:856-863`); `:829` changes to "a release carries no payload; a cancel of a claimant intent carries exactly a CANCEL_COSIGN, a cancel of a residual is refused as today":
   - `q = (H − v.lastCancelHeight < CANCEL_QUIET) ? v.cancelCount : 0`; `required = min(q + 1, CANCEL_SIGNERS_MAX)`.
   - Every entry must: recover (low-S) under `CancelStatementMessage` to a key `K`; `K` is the attestor key of the mirror record named by `seq`, which is that key's **newest** record, with status `ELIGIBLE` or `DORMANT`, `bondSpentHeight == 0`, `!Frozen()` — **read from the module's mirror at this transaction** (the overlay after every earlier transaction of the block); keys distinct; `priceMicroUsd` in `[PRICE_MIN, PRICE_MAX]`; and **C4b**: `!IsUnderwater(claimingVault.collateralZat, price, claimingVault.mintedCents, claimPath == 'a' ? claimThresholdBps : emergencyRatioBps)` — "at your reference height this vault was not claimable by your path". Any failing entry → `intent-cancel-cosign` (`INTENT_CANCEL_COSIGN`, `state.h:116` block; block verdict `bad-yellowback-intent-cancel-cosign`). `count ≥ required`, else the same verdict.
   - On success: `v.cancelCount = min(q + 1, 255)`, `v.lastCancelHeight = H`, written with the re-created record (`:879-886`). Log the co-signer seqs in `log.bundleSeqs` (so `yed_gettxinfo` shows who cancelled — closes 03/V-2's "consensus does not record the canceller" for co-signers).
   - **Membership at same-block joins/evictions (W3-Y-3 item 3), stated in the spec:** counted against the mirror *at the transaction*. A member that joined in this block is `PENDING` (maturity = `BOND_MATURITY`, `module.cpp:47`) and never counts; a member ejected (EQV-1), withdrawn, removed by its own exit or **evicted earlier in the same block** has left `ELIGIBLE/DORMANT` in the overlay and does not count; one evicted later in the block counted at this transaction's position. This is strictly stronger than the interpreter's parent-snapshot `IsCurrent` (`vault/state.cpp:195-198`) — the module may refuse a cancel the interpreter accepts, never the reverse — and it is deterministic in block order on both lines. A `PENDING` record that the primitive already treats as current (bond below the D-Q-30 floor) does not count: stricter, accepted.
   - **Liveness:** the `"YC"` blob is not a bundle (`"YA"`), so `AttestationLiveness` (`state.h:362`) credits nobody from it and `LIVENESS_UNHELD` (`state.cpp:1309-1316`) does not fire; assert this with a test on both hooks (`module.cpp:143-166`, `state.cpp:1291-1322`).
5. **EQV-1 accepts a cancel statement as one side (C4b).** Extend `EquivocationEvidence` (`state.h:294`) with a second evidence form: a regular attestation `A` plus a cancel statement `S` = `(intentOutpoint, seq, price, sig)` from a CLAIM_CANCEL transaction, `A.seq == S.seq`, `A.citedHeight == S.citedHeight`, prices differ. `EquivocatedBy` verifies `A` under `AttestMessage` and `S` under `CancelStatementMessage` with the same key and `blockHash(citedHeight)`. Both callers (`module.cpp:96-110` `Ejections`, primitive side; `state.cpp:973-998` `ApplyEquivocation`, mirror) go through these two functions, so the change is one place; the meaning of EQV-1 ("two prices at one height") is unchanged and D-Q-29 is not reopened. The `EQUIVOCATION` payload (0x07) gains a form byte; the existing form stays byte-identical. Add the statement message to `yellowback_attest_vectors.json` (both lines, byte-identical, enforced by `MEDIUM-W3-P-2`'s manifest; no client vendors this file at x402-ycash `6af477a`, yb-calibration `97d5279`, YEW or Hawkeye, so nothing re-pins).
6. **Why the entries live outside the outputs.** `set_signcancel` signs `SIGHASH_ALL|ANYONECANPAY` (MEDIUM-01-V-2): outputs are covered, other inputs are not. Keeping the count and entries out of the OP_RETURN lets agents **add co-signatures after the set member has signed** (e.g. after a reorg raised `required`, design A-6) by swapping the carrier input, without a second set signature over the same prevout — which would be a provable `SET_EQUIVOCATION` against the signer. A relay that strips or swaps the carrier can only make the cancel *invalid* (fewer entries), never void-but-valid, so the W7 hazard that forced committed carriers for mints does not apply; the carrier stays hash-committed only because the W2 parser requires it.
7. **RPCs** (additive; no `rpcversion` bump under `doc/yellowback-rpc.md`'s rule; OPTIONAL in the contract JSON):
   - `yed_getvault` / `yed_listvaults`: `cancelCount`, `cancelsRequired` (at tip + 1), `cancelQuietUntil` (`lastCancelHeight + CANCEL_QUIET`).
   - New `yed_signcancelstatement "intentoutpoint" ( priceMicroUsd )`: signs one entry with the node-held member key. **Sign-once:** it goes through `SignAttestationGuarded`'s persisted guard (`txbuilder.cpp:1805-1853` dd / `:1966-2014` ycash6) keyed on `(seq, claimRef, blockHash(claimRef))`: if the member already attested at `claimRef` it must use that price (refuse a different one with `equivocation-guard`); a new price is recorded before signing; refuse a price that fails the C4b test (it would be invalid and is a statement the member does not hold). Refuse unless the claim is **confirmed** (template-spend txids are malleable until then, design A-6).
   - `yed_buildcancel` (`yellowbackwallet.cpp:1805-1878`) gains `entries[]` (hex), builds the `0x09` OP_RETURN and the `"YC"` carrier (funded from the wallet), refuses with fewer than `cancelsRequired` entries, and returns `cancelsRequired`. A `yed_addcancelentries "hex" entries[]` (or the same RPC with the signed hex) swaps the carrier of an already-signed cancel without touching the set signature.
8. **Attestor agent** (`contrib/yellowback/attest/`): a watcher for confirmed claims whose `claimRef` price (its own) says "not claimable"; publishes its entry on the existing iroh-gossip topic (`dir` transport in tests); gathers up to `CANCEL_SIGNERS_MAX` (extras are valid); hands the cancel to the operator flow. Today cancels are operator-driven; keep that, add the gathering.
9. **Spec and plans:** `yellowback-cancel-limit-design.md` header → "implemented (fix/W3-Y-2-cancel-limit)" and the "outside the outputs" rationale of step 6 (this report owns only these two design-doc edits; the co-signer membership paragraph, the per-vault counter sentence and C4b "deterrent only, not counted toward the bound" are owned by `MEDIUM-W3-Y-3-…` §4 step 4, whose text follows step 4 above); U-24 "given up (iii)" (`yellowback-upgrade-plan.md:1288`) → the bound (one free 12 h round per vault per week; five colluding seats block); `doc/yellowback-spec.md` CAN-2 section; `doc/yellowback-attestor.md` "cancel statements are price statements: never sign one at a height where your own attestation says the vault was claimable"; `docs/mapping.md` §22 row ("a set-level threshold has no per-vault memory; the module keeps it").
