## 1. Finding

`vault_send "hex"` (`ycash-dd/src/rpc/vault.cpp:2105-2120`) is three statements: `DecodeMutable` → `SignWalletInputs` → `Broadcast`. `SignWalletInputs` (`:947-961`) signs, with `SIGHASH_ALL`, **every** input whose coin `GetCoin` finds, that is not a V/I template, and that is `ISMINE_SPENDABLE` — no check that this wallet built the transaction, chose the coin, or that the coin's value goes anywhere in particular. `Broadcast` (`:963-979`) refuses only `YedFeeOverCap` (`src/policy/policy.cpp:538-547`, `valueIn − valueOut > YedMaxTxFee()`); value paid to a third-party output is not a fee, so it passes. `set_sendact` (`:1457-1472`) is the same plus `FindAct` (a decodable act output). Neither returns anything but the txid, so there is no preview. 07/NEW-2: `vault_send` does not even call `FindTemplateInput`, so the hex need not be a vault spend at all — any transaction is signed and broadcast.

Exploit: the documented multi-party flow hands transaction hexes between operators (`doc/vault-rpc.md:300-470`: a builder's unlock goes round for `set_signunlock`, a member re-funds with `vault_refee` and sends with `vault_send`; `set_buildact` hexes go round for `set_signact` and come back for `set_sendact`). A counterparty who knows one of the operator's P2PKH outpoints (transparent and public — e.g. the change of the operator's bond-funding transaction) sends a hex whose "fee input" is that coin and whose outputs pay the counterparty. One `vault_send` (or `set_sendact`) by the operator signs the coin away and broadcasts it. The verifier narrowed it to Medium: the documented flow says "the node that funded the spend must send it" (`doc/vault-rpc.md:470`), Hawkeye only `vault_send`s hexes from its own store (`hawkeye/crates/hawkeye/src/engine/sign.rs:486-521`) and refuses unlocks whose fee inputs it does not own (`burn.rs:297-302`), YecWallet sends only its own builds — so this is a one-step, no-preview signing of arbitrary wallet coins reached by an operator misusing a hand-off RPC, not a push-button theft against the automated attestor. Identical on `ycash6` (`src/rpc/vault.cpp:964-978` `SignWalletInputs`, `:980` `Broadcast`, `:1478` `set_sendact`, `:2126` `vault_send`).

## 2. Root cause

- `src/rpc/vault.cpp:947-961` (ycash6 `:964-978`) — `SignWalletInputs` has one mode, "sign whatever is mine"; it is used both by builders that just funded the transaction themselves (`vault_lock`/`set_create`/`set_join` style one-shot RPCs, `ExactCoin`'s split at `:878-882`, `vault_release` `:2177-2178`) and by the hand-off senders `vault_send` / `set_sendact`, where the hex came from outside.
- `src/rpc/vault.cpp:758-790` (`Fund`) and `:866-885` (`ExactCoin`, which since refee-utxo also takes a `replacing` set) lock the coins they choose with `LockCoin` (`:789`, `:874`, `:883`) — in memory only — and record nothing about which outputs those coins were chosen to fund. Only unlock/cancel builds are remembered persistently (`vaultbuild`, `RememberBuild` `:849-856`; re-locked at load by `CWallet::LoadVaultBuild`, `src/wallet/wallet.cpp:7654-7660`); `vault_app` (`:2268-2298`) and `set_buildact` (`:1387-1428`, via `BuildActTx` `:1099-1106`) are not.
- `src/rpc/vault.cpp:2105-2120` (ycash6 `:2126-2141`) — `vault_send` never calls `FindTemplateInput` (`:1614-1637`), unlike `vault_refee` (`:1984`).
- `src/rpc/vault.cpp:963-979` (ycash6 `:980-996`) — the only value check is the fee cap.

## 3. Fix options considered

1. **Sign only coins this wallet's vault builders chose, and only into the outputs they were chosen for (recommended).** Every builder that funds a hand-off transaction records `feeInput → outputsDigest`; the senders sign an input only if it is recorded and the hex's outputs digest matches. A counterparty's hex either names an unrecorded coin (refused) or a recorded coin with other outputs (refused). Covers unlocks, cancels, APP spends, act transactions and re-funds with one mechanism, survives restarts (persisted, like `vaultbuild`).
2. **Sign only wallet-*locked* coins** (`IsLockedCoin`). Cheap, but (a) locks are in memory only, so a node restart between `set_buildact` and `set_sendact` (Hawkeye's slash flow: `slash.rs:694` build → votes → `:769` send) makes every legitimate send fail; (b) `lockunspent` locks are user-set for the opposite purpose (to protect a coin); (c) a locked coin would still be signable into *any* outputs. Rejected as the main guard.
3. **Net-outflow bound only** (`Σ signed inputs − Σ outputs to own scripts ≤ YedMaxTxFee()` unless `allowoutflow`). Blocks the theft shape but also blocks legitimate builds whose outflow is not "to own scripts" (a `SET_JOIN`'s bond output, a re-fund of a foreign build whose change belongs to the builder — W3-N-2), and leaves "sign whatever is mine" as the default. Kept as a **second, independent check** with an explicit override, not as the guard.
4. **Doc-only** ("never `vault_send` a hex you did not build"). Already said (`doc/vault-rpc.md:470`) and not enforced; rejected.

## 4. Recommended fix

1. **The funded-coin registry (wallet).** New in-memory `std::map<COutPoint, uint256> CWallet::mapVaultFeeInputs` (coin → outputs digest) and wallet record `("vaultfeein", outpoint) → uint256 outputsDigest` in `src/wallet/walletdb.{h,cpp}` (`WriteVaultFeeInput` / `EraseVaultFeeInput`, a `ReadKeyValue` branch that calls `CWallet::LoadVaultFeeInput`, which also re-inserts the coin into `setLockedCoins` exactly as `LoadVaultBuild` does at `wallet.cpp:7654-7660`). Add `"vaultfeein"` to the record types carried by `dumpwallet`/`z_exportwallet` and `importwallet` (the 07/F-5 code in `rpcdump.cpp` already does this for `vaultbuild`; follow it) **and** to the salvage key-type list of `MEDIUM-W3-07-NEW-1`.
   - `OutputsDigest(const CMutableTransaction&)` in `src/rpc/vault.cpp`: SHA256d over the serialized `vout`, where every act output (`IsActOutput`) is first replaced by `EncodeAct(act with sigs cleared)` — `set_signact` rewrites the act output with signatures (`SignActInPlace`, `:1001-1085`), so the digest must not depend on them; template inputs' scriptSigs never enter it (inputs are not in it at all).
2. **Record at every hand-off builder.** Give `Fund` and `ExactCoin` an out-parameter (or return) of the coins they chose; after the build is final (outputs fixed), the caller writes `vaultfeein` for each chosen coin with the build's `OutputsDigest`:
   - `vault_buildunlock` (`:1733-1795`) and `BuildIntentCancel` (`:1832-1913`, which serves `vault_buildcancel` and `yed_buildcancel` through `BuildYedIntentCancel` `:2306`) — alongside `RememberBuild`;
   - `vault_app` (`:2268-2298`) — after `Fund`;
   - `set_buildact` / `BuildActTx` (`:1099-1106`) — after `Fund`;
   - `Refee` / `vault_refee` (`:891-943`, `:1960-2006`) — for the coin `ExactCoin` returns, with the (unchanged) outputs digest of the re-funded hex. `ExactCoin`'s out-parameter must coexist with its refee-utxo signature `ExactCoin(value, exclude, replacing)` (`:866`; ycash6 `:883`) — or with the side-effect-free `PickExactCoin` / `BroadcastSplit` split that `LOW-W3-N-2-W4-N-2-N-3-N-4` introduces — and the registry write must happen only after `Refee`'s checks pass: **record nothing** on its refusal paths (today the "spent or replaced input" refusal `:924-928` and the fee refusal `:932-937`; ycash6 `:941-945`, `:949-954`), which release the new coin, nor on the `SetSighash` mismatch throw (`:915-916`). A re-fund of a foreign hex is the one place a coin is attached to outputs this wallet did not build; that is bounded by `LOW-W3-N-2-W4-N-2-N-3-N-4-ycash-vault-refee-cap-lock-release.md` (cap / `maxfund`), which must land with or right after this report.
   - One-shot RPCs that fund, sign and broadcast in the same call (`vault_lock`, `set_create`, `set_join`, `set_heartbeat`, `set_leave`, `vault_release`, `vault_ownerspend`, `ExactCoin`'s split) keep calling the unrestricted signer: the hex never leaves the node.
3. **Two signers.** Split `SignWalletInputs` (`:947-961`) into `SignOwnBuildInputs(mtx)` (today's behaviour, for the one-shot builders) and `SignHandoffInputs(mtx, const Options&)` for `vault_send` / `set_sendact`:
   - compute `digest = OutputsDigest(mtx)`;
   - for each input with a wallet-spendable P2PKH coin: sign iff `mapVaultFeeInputs[prevout] == digest`; otherwise collect it as *foreign-to-this-build*;
   - if any wallet-spendable input was collected, refuse with `RPC_WALLET_ERROR` `vault-send-foreign-input: input <n> (<outpoint>, <amount>) is this wallet's coin but was not chosen by this wallet for these outputs; nothing was signed`, unless `options.allowinputs` lists exactly those outpoints (an explicit, per-call override for an operator who knowingly co-funds; documented as dangerous);
   - then compute `outflow = Σ(value of inputs signed here) − Σ(outputs whose scriptPubKey IsMine(ISMINE_SPENDABLE))` and refuse when `outflow > YedMaxTxFee()` unless `options.allowoutflow ≥ outflow` — with the JOIN exception that an act output of type `SET_JOIN` whose `memberKey` this wallet holds counts its `vout[bondVout]` as own (the bond is the member's money). This is the independent belt for option 3 above.
4. **`vault_send` requires a template input (07/NEW-2).** Call `FindTemplateInput` (`:1614-1637`) first and refuse "no unspent vault or intent input" exactly as `vault_refee` does (`:1984`); `set_sendact` keeps its `FindAct`.
5. **Preview.** Both RPCs take an optional second argument `{"dryrun": bool, "allowinputs": [outpoint], "allowoutflow": amount}`. `dryrun: true` returns, without signing or broadcasting: `{"template": {"outpoint","kind","selector"} | null, "act": ActJSON | null, "sign": [{"vin","outpoint","amount"}], "foreign": [{"vin","outpoint","amount"}], "outputs": [{"n","amount","address"|"script","mine","kind"}], "fee", "outflow", "wouldrefuse": reason | null}`. Wrappers (YecWallet, Hawkeye's CLI) show it before sending. The non-dryrun result stays `"txid"` (contract-compatible); errors carry the same fields in the message.
6. **Housekeeping.** Extend `PruneVaultBuilds` (`:835-846`) to drop `vaultfeein` entries whose coin is spent in the chain (keep them while the spend is only in the mempool) and unlock them; call it from `vault_send`/`set_sendact` too.
7. **Docs.** `doc/vault-rpc.md` `vault_send` (`:464-470`) and `set_sendact` (`:256-262`): "signs only this wallet's coins that this wallet's builders (`vault_buildunlock`, `vault_buildcancel`, `yed_buildcancel`, `vault_app`, `set_buildact`, `vault_refee`) chose for exactly these outputs; refuses any other wallet coin (`vault-send-foreign-input`) and an outflow above the fee cap (`vault-send-outflow`); `dryrun` previews". Error table (`:515+`) gains both reasons; `doc/vault-rpc-contract.json` gains the options object and the dryrun result shape (bump nothing else). `ycash6/doc/vault-rpc.md` is the same text (the files differ only from line 500 on).

## 5. Tests

- **Functional `qa/rpc-tests/vault_rpc.py` (both lines) — the case that would have caught it:** node 1 builds, with `createrawtransaction`, a transaction spending one of node 0's P2PKH coins (a vault template input added or not) to a node-1 address; `n0.vault_send(hex)` → `vault-send-foreign-input` (with a template input) / "no unspent vault or intent input" (without); `n0.set_sendact` of an act transaction carrying the same foreign input → refused; node 0's balance unchanged; `dryrun` lists the coin under `foreign` and `wouldrefuse`.
- **Same file, positive paths:** the existing unlock → `set_signunlock` ×k → `vault_send` (`:221-228`), the cancel by one member (`:289`), the pre-signed cancel (`:321-326`) still pass; `vault_rpc.py:262` ("node 1 cannot sign node 0's fee inputs") now fails with `vault-send-foreign-input`'s sibling (no recorded coin on node 1: nothing to sign → the broadcast fails as today) — assert the reason, not `''`.
- **Restart persistence:** `set_buildact` on node 0 → `stop_node`/`start_node` → `set_signact` on the cosigners → `n0.set_sendact` succeeds (registry reloaded, coin re-locked); the same for `vault_app` → restart → `vault_send`.
- **`vault_refee.py`:** a member re-funds a foreign signed unlock (its own `ExactCoin` coin recorded against the hex's outputs) → `vault_send` signs it; altering any output of the re-funded hex → refused.
- **Outflow belt:** a remembered build whose outputs were tampered to keep the same digest cannot exist (digest binds outputs); unit-test `OutputsDigest` stability across `set_signact` (act sigs added) and across `vault_refee` (inputs replaced).
- **`vault_rpc_contract.py`:** the options object and the dryrun shape.
- **Devnet:** `contrib/yellowback/devnet/bridge-sim` (`:203`, `:334`, `:473`) and `upgrade-walk` unchanged in flow, against both binaries.

## 6. Acceptance criteria

- `vault_send` and `set_sendact` never sign a wallet coin that this wallet's vault builders did not choose for the hex's exact outputs, unless the call names it in `allowinputs`; never sign when the wallet's net outflow exceeds the fee cap, unless `allowoutflow` covers it; `vault_send` refuses a hex with no template input.
- Every legitimate flow in `vault_rpc.py`, `vault_refee.py`, `vault_slashing.py`, `vault_bridge.py`, the devnet bridge-sim and Hawkeye's integration suite (against both binaries) passes unchanged, including across a node restart between build and send.
- `dryrun` exists, is in `doc/vault-rpc-contract.json`, and reports the inputs it would sign and the outflow.
- The new record is dumped/imported and kept by salvage (with `MEDIUM-W3-07-NEW-1`).

## 7. Risks and side effects

- **No consensus effect.** A stricter sender can only refuse.
- **Client impact:** any client that builds with `createrawtransaction` + wallet coins and then calls `vault_send` breaks (by design); Hawkeye and YecWallet use the node's builders and are unaffected; check Hawkeye's mock (`crates/hawkeye-ycash/src/mock.rs`) mirrors the new refusal so its tests keep meaning. A wallet upgraded with builds in flight has no `vaultfeein` records for them: on first load after the upgrade, derive records from existing `vaultbuild` memos (their fee inputs, their outputs digest); for an in-flight `set_buildact`/`vault_app` hex, the operator rebuilds or uses `allowinputs` once.
- **Liveness:** a re-fund whose new coin is not recorded (e.g. `vault_refee` on a node older than this change) cannot be sent until rebuilt; acceptable.
