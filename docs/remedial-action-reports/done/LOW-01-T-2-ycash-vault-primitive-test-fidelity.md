## 1. Finding

The vault primitive's unit suite is substantive — `vault_vectors.json` is generated by the pure-Python model and replayed byte-for-byte, and `vault_state_tests.cpp` asserts exact reject reasons for 34 rules — but six evidentiary gaps remain, each confirmed by the second wave. (T-2) `set_sig_checker` signs and verifies under `branch = 0` and never asserts that a set signature over another branch ID, another prevout or another amount is refused; the "bound to the outpoint" comment is backed only by a different-`scriptCode` case. (T-3) Every `OP_CHECKSETSIG` script test uses `MockSetChecker`; no unit test runs a real V/I script through `VerifyScript` with the real `SetSigChecker` over a real `SetSnapshot` — the only such coverage is the functional `vault_primitive.py`, i.e. the slow tier. (T-4) The pre-activation parity test covers 0xc0/0xc1 in a scriptPubKey, executed and unexecuted, but not in a scriptSig. (T-5) The fuzz target reaches the parsers only; nothing fuzzes `ApplyTx`/`ApplyBlock`. (T-6) The restart section exercises clean restart, SIGKILL and a wiped `vaults/` directory with post-activation shapes only; the pre-activation I-coin case of 01/V-1 is absent (and would fail today, which is the point).

(07/F-4) Commit `055d9c2` removed the stock node from the devnet walk's vault-state-hash comparison — correctly, because on regtest the attestor set is a per-node parameter and the YED module's liveness hook writes `MemberRecord.lastAct` only where the module has an adopted set. But the replacement (same tip on all eleven nodes) is weaker: a node that accepts the same blocks with a different set state now passes, and the one independent implementation of the set state, the Python `VaultModel`, is not run over the walk at all — its optional module liveness hook (`db1831d`) exists but is wired nowhere. A shared C++ hook bug is invisible.

## 3. Fix options considered

- T-3: (a) replay the vectors' `spends[]` through `VerifyScript` with a `SetSigChecker` over a snapshot rebuilt from the vectors' `keys`/`acts`; (b) build a fresh set in `vault_state_tests.cpp` with the existing `Chain`/`SetWithMembers` fixture and sign with `SignRecoverable`. (b) is accepted: it already has real keys, a real `MemoryKV` snapshot and the negative-member cases; (a) needs the vector generator to emit the set's acts in a replayable order — worth doing later for cross-line parity, not now.
- T-5: a new target `src/fuzzing/VaultState/` versus extending `Vault/`. New target accepted: the existing corpus generator (`src/test/gen_vault_corpus.py`) and replay table stay as they are; the workflow glob `Vault*` picks the new directory up without a workflow change.

## 5. Tests

- Every item in §4 is itself a test; the proof that each would have caught its defect:
  - T-2 negatives fail if `CheckSetSigs` ever drops `consensusBranchId`, the prevout or the amount from what it signs (e.g. a future ANYONECANPAY change — R5 — that forgets to keep the prevout bound).

  - F-4's member diff fails on any stock/module divergence outside `lastact`; the two-model replay fails on a shared C++ hook bug (both node classes disagree with their witness).
