## 1. Finding

Before `UPGRADE_VAULT`, V- and I-shaped outputs are refused by **policy only** (`ycash-dd/src/policy/policy.cpp:131-134`, `whichType == TX_VAULT_INTENT && !vaultActive`); `ConnectBlock` never calls `IsStandardTx`, so a miner can include `tx0 = {vout[0]: a well-formed intent I, vout[1]: P2PKH}` before activation and leave `vout[1]` unspent. After activation that I coin is a template input (`src/vault/state.cpp:466-471` classifies by shape alone) and spendable: the RELEASE branch is `OP_DROP <delay> OP_CHECKSEQUENCEVERIFY` with no signature (`src/vault/template.cpp:208-209`), BIP68 (`main.cpp:797-833`) is satisfied by any coin older than `delay`, and I-1 needs only an output ≥ value to the `recipientHash` the attacker wrote (`state.cpp:533-538`). The live path reads the real coin height from the chainstate (`main.cpp:3262-3270`, `c.height = coins->nHeight`) and accepts the block.

On start-up, when the vault DB is behind the chain, `Reconcile` (`src/vault/node.cpp:273-355`) replays blocks from disk with `CoinsFromUndo` (`:67-99`): a spent coin's height comes from the undo record (`CTxInUndo.nHeight`, written **only when the spend empties the `CCoins` entry**, `main.cpp:2466-2470`), else from the block, else from the `'v'` template-output index (filled only by `ApplyTxInner` from activation, `state.cpp:565-575`), else — for any I-shaped coin — **`return false`** (`node.cpp:90`). `Reconcile` turns that into `"block %d's undo data does not give its spent coins"` (`:338-340`) and `init.cpp:1956-1958` into `InitError("… Restart with -reindex …")`. Replay is reached on an unclean shutdown (the vault DB commits with `WriteBatch(batch, false)`, `db.cpp:144`, and syncs only with the chainstate flush, `main.cpp:3611`), on a wiped `vaults/` directory, and on **every `VAULT_DB_VERSION` bump** (`db.h:53`, already at 3 — every record-layout release replays from activation on every node). So one cheap pre-activation preparation plus one post-activation spend makes the next format-bump release un-startable network-wide without `-reindex`, and un-startable at all on a pruned node (01/N-1: the `-prune` refusal lives only under `yellowback::g_yellowbackLive`, `init.cpp:1381-1384`, so a node without a YED attestor set — every mainnet node today — may prune the very `blk`/`rev` files `Reconcile` reads). Pre-activation V-shaped coins have the sibling problem (01/V-3): never indexed, never counted in `lockedValue`, never seen by a module's `ValidateCreate`. The unit test `coins_from_undo` (`src/test/vault_state_tests.cpp:945-950`) asserts the `return false` as *desired* (01/T-1). No funds move; the class is availability. `CoinsFromUndo` and the hooks are identical on `ycash6` (`src/vault/node.cpp:91-92`, `src/main.cpp:2781`, `:3874`, `src/init.cpp:1542-1543`, `:2216`, `src/test/vault_state_tests.cpp:946-950`).

## 2. Root cause

- `src/vault/node.cpp:85-92` — the fourth branch of `CoinsFromUndo`: `if (MatchIntent(c.scriptPubKey, ip) != Shape::NONE) return false; c.height = 0;` — replay has no source for the height of an unindexed I-shaped coin, and the height *is* consensus input (I-2, `state.cpp:540`).
- `src/vault/state.cpp:446-479` — `ApplyTxInner` classifies template inputs by `ParseVault`/`ParseIntent` on the spent script with no height check: a coin created before the rules existed is a template input after them.
- `src/main.cpp:2466-2470` — v4.5.0's per-transaction `CCoins` undo carries `nHeight` only on the emptying spend (the `Coin` vs `CCoins` row of `docs/mapping.md` §3).
- `src/init.cpp:1381-1384` — `-prune` refused only when Yellowback is live; `:1051-1060` refuses `-prune` with `-txindex`/`-rescan` only.
- Plan: `yellowback-upgrade-plan.md:882` ("a template-output index is **not** needed") is false — the index is I-2's replay input (01/V-11).

## 3. Fix options considered

1. **Consensus activation floor + replay derives 0 (recommended).** A template input whose coin was created below the activation height is invalid. Then a pre-activation coin's true height is never consensus input, live and replay agree by construction, and V-3 (the whole pre-activation class) closes with it. One rule, no new state.
2. **Record every consumed template coin's height in the vault `BlockUndo`** (07/F-3's first suggestion). Non-consensus, but it only papers over this instance of the live-vs-replay seam: the pre-activation V/I class stays spendable (V-3), the index stays non-consensus-but-load-bearing, and `Reconcile` keeps a second source of truth. Rejected.
3. **Refuse a template input that is not in the `'v'` index** (07/F-3's second suggestion). Equivalent effect to (1) — every post-activation template output is indexed (`state.cpp:565-575`) — but it makes a *database* the rule's input instead of a *height* and is harder to state in the spec and to mirror in the Python model. Rejected in favour of (1); note that (1) still makes the index a consensus structure for I-2's replay (it already is), so §15.4 is corrected either way.
4. **Soft-fail `Reconcile` on a pruned range (migrate records in place).** Rejected: a layout bump needs the replay; in-place migration is a second implementation of every record change.

**Rule-4 four-part check (PR body).** DigiByte does **X** = give every spent output its creation height on replay, in **Y** = `ref/digibyte/src/validation.cpp` (`DisconnectBlock`/`UndoCoinSpend`), using mechanism **M** = the per-output `Coin` model, whose undo entry carries the full `Coin` (height included) for every spend. The Ycash equivalent **Z** = the per-transaction `CCoins` model with `CTxInUndo` (`ycash-dd/src/main.cpp:2466-2470`), which lacks **M**: the height is recorded only on the spend that empties the entry. So the adaptation **W** = (i) a template rule **S-0** that a template input's coin height must be ≥ the activation height, so the height of a coin the rules never indexed is never an input to them, and (ii) `CoinsFromUndo` deriving height 0 for an unindexed template-shaped coin, which S-0 rejects exactly as the live path rejects the real pre-activation height.
**In-tier ladder answer.** A **template rule** (the lowest rung: no opcode, no transaction field, no new state — the existing `'v'` index is acknowledged as consensus input); per-vault (per-coin), not global. Why no cheaper rung: policy cannot help (the preparation is miner-only and already bypasses policy); a replay-only change (option 2) leaves V-3 and the seam open.

## 4. Recommended fix

1. **S-0, the activation floor** — `src/vault/state.cpp`, `ApplyTxInner`, inside the input loop right after a template shape is recognised (`:466-470`, before `if (tin) return "bad-txns-vault-multi"`): `if (c.height < activationHeight) return std::string("bad-txns-vault-preactivation");`. Only MATCH shapes reach this point (a MALFORMED-shaped coin `continue`s at `:468-470` and is spent by whatever its script accepts — unchanged, and its height is not consensus input). A coin created *in* the activation block (`h == activation`, the first block `ApplyTxInner` runs for) is at or above the floor and is indexed, so it passes.
   - `VaultState` needs the activation height: add `void SetActivationHeight(int64_t h)` beside `SetBlockHashes` (`src/vault/state.h:395`), default 0 (no floor — unit tests that build chains from height 0 keep working; the node asserts it is set). Set it from `params.vUpgrades[Consensus::UPGRADE_VAULT].nActivationHeight` at every construction: `src/main.cpp:3408` (ConnectBlock), `src/miner.cpp:386` (the running copy; the trial at `:580` copies it), `src/vault/node.cpp:342` (Reconcile), and inside `vault::CheckTx` / `RecheckMempool` (`node.cpp`, the mempool evaluation at tip+1). Mempool coins at `MEMPOOL_HEIGHT` read as `mempoolHeight` (`node.cpp:63`) ≥ activation — unaffected.
   - Verdict string `bad-txns-vault-preactivation` (new; add to `doc/vault-rpc.md`'s reject-reason list and `doc/vault-rpc-contract.json` if it enumerates reasons).
2. **`CoinsFromUndo`** — `src/vault/node.cpp:85-92`: delete the `MatchIntent(...) != Shape::NONE) return false;` line; every unindexed, non-emptying, out-of-block coin gets `c.height = 0`. ## 7. Risks and side effects

- **Chain split:** a consensus rule; both lines land together and before any public activation height (none set). No regtest/devnet chain survives (wipe).
- **Vector freeze:** `vault_vectors.json` is unchanged (no template, act or message change). The golden state vector of the YED module is unaffected (its chains create every template output after activation).
- **Operational:** a node that already pruned on a network that later sets an activation height is refused at start after upgrading — the error message must say "re-download without -prune" (there is no `-reindex` on a pruned node). Release notes on both lines.
- **Mempool:** a pre-activation V/I coin can never be spent through the template path; its owner's funds are not lost — the V's owner branch is also a template spend and is refused, so **a V created before activation is unspendable by template forever** (its value was never meant to exist; policy refused it; miner-only). State this in the spec as given up.
