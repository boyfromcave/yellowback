getwalletinfo ( asOfHeight )
Returns wallet state information.

Arguments:
1. asOfHeight       (numeric, optional, default=-1) Execute the query as if it
                    were run when the blockchain was at the height specified by
                    this argument. The default is to use the entire blockchain
                    that the node is aware of. -1 can be used as in other RPC
                    calls to indicate the current height (including the
                    mempool), but this does not support negative values in
                    general. A “future” height will fall back to the current
                    height. Any explicit value will cause the mempool to be
                    ignored, meaning no unconfirmed tx will be considered.

With asOfHeight the balance fields are counted afresh at that height, as getbalance asOfHeight counts them.

Result:
{
  "walletversion": xxxxx,     (numeric) the wallet version
  "balance": xxxxxxx,         (numeric) the total confirmed transparent balance of the wallet in YEC
  "unconfirmed_balance": xxx, (numeric, optional) the total unconfirmed transparent balance of the wallet in YEC.
                              Not included if `asOfHeight` is specified.
  "immature_balance": xxxxxx, (numeric) the total immature transparent balance of the wallet in YEC
  "balance_ecc": xxxxxxx,     (numeric) balance minus balance_pq: every coin of balance that is not post-quantum
                             (P2PKH, P2PK, P2SH)
  "balance_pq": xxxxxxx,      (numeric) the part of balance held by post-quantum addresses (TX_PQPKH)
  "unconfirmed_balance_ecc": xxx, (numeric, optional) unconfirmed_balance minus unconfirmed_balance_pq.
                              Not included if `asOfHeight` is specified.
  "unconfirmed_balance_pq": xxx,  (numeric, optional) the part of unconfirmed_balance held by post-quantum addresses.
                              Not included if `asOfHeight` is specified.
  "pq_by_scheme": [           (array) balance_pq and unconfirmed_balance_pq by scheme, both schemes always
    {
      "pqscheme": n,              (numeric) 1 or 2
      "pqschemename": "name",     (string) "SLH-DSA-SHA2-128s" (1) or "FN-DSA-512" (2)
      "balance_pq": xxx,          (numeric) this scheme's part of balance_pq
      "unconfirmed_balance_pq": xxx (numeric, optional) this scheme's part of unconfirmed_balance_pq;
                                  not included if `asOfHeight` is specified
    }, ...
  ],
  "shielded_balance": xxxxxxx,  (numeric) the total confirmed shielded balance of the wallet in YEC
  "shielded_unconfirmed_balance": xxx, (numeric, optional) the total unconfirmed shielded balance of the wallet in YEC.
                              Not included if `asOfHeight` is specified.
  "txcount": xxxxxxx,         (numeric) the total number of transactions in the wallet
  "keypoololdest": xxxxxx,    (numeric) the timestamp (seconds since GMT epoch) of the oldest pre-generated key in the key pool
  "keypoolsize": xxxx,        (numeric) how many new keys are pre-generated
  "yed_held": true|false,     (boolean) this wallet has held YED or issued a YED holder key (a write-once
                             wallet.dat marker): start-up refuses it where Yellowback is not live, unless -yellowback=0
  "yed_unlocked": true|false, (boolean) true exactly when yed_held is true and Yellowback is not live (the node was started
                             with -yellowback=0, on the command line or in the config file): this wallet's YED outputs are
                             not locked, and a send that spends one destroys the YED it carries
  "unlocked_until": ttt,      (numeric) the timestamp in seconds since epoch (midnight Jan 1 1970 GMT) that the wallet is unlocked for transfers, or 0 if the wallet is locked
  "paytxfee": x.xxxx,         (numeric) the preferred transaction fee rate used for transactions created by legacy APIs, set in YEC per 1000 bytes
  "mnemonic_seedfp": "uint256", (string) the BLAKE2b-256 hash of the HD seed derived from the wallet's emergency recovery phrase
  "legacy_seedfp": "uint256",   (string, optional) if this wallet was created prior to release 4.5.2, this will contain the BLAKE2b-256
                                    hash of the legacy HD seed that was used to derive Sapling addresses prior to the 4.5.2 upgrade to mnemonic
                                    emergency recovery phrases. This field was previously named "seedfp".
  "has_external_imports": true,   (bool, optional) only present and true when the wallet contains keys imported from outside the ZIP-32
                                    derivation tree (importprivkey, z_importkey, importwallet). When set, the recovery phrase alone is NOT
                                    a complete backup. Back up wallet.dat or run z_exportwallet to capture the imported keys.
  "external_imports_warning": "...", (string, optional) human-readable warning, only present when has_external_imports is true.
  "lookahead_incomplete": true|false, (bool) true when the wallet may have missed a transparent coin: while encrypted and locked
                                    (when it cannot derive the keys of the addresses of its seed it has not issued; it
                                    watches the next -keypool + 1 of each chain by their key IDs, a payment to one being a
                                    watch-only coin until walletpassphrase) it saw a block transaction paying an address of
                                    its seed that leaves fewer than -keypool + 1 addresses it holds or watches beyond it, so
                                    a later payment past them would be missed; or a write of a key it saw paid failed. An
                                    ordinary block, a wallet whose seed no other wallet uses and a locked restart set
                                    nothing. (A wallet encrypted by an older release and not unlocked since cannot tell, and
                                    is set by a new block with an output it cannot check.) Kept in the wallet file; the remedy
                                    is a rescan of the missed range with the wallet unlocked, which clears it: an import RPC
                                    with rescan (importprivkey, importpubkey, importaddress, importwallet, z_importkey,
                                    z_importviewingkey, z_importwallet) run while unlocked, or -rescan for an unencrypted
                                    wallet; an encrypted wallet's start-up scan (-rescan included) always runs locked. Or
                                    restore the recovery phrase into a new wallet file (-wallet=<new file> -mnemonicfile=<file>),
                                    which finds the coin.
  "restore_in_progress": true|false, (bool) true while the wallet, created from a recovery phrase (-mnemonicfile), has not
                                    completed its scan of the chain from genesis: its balances and transactions may be
                                    incomplete. Every start of the node scans from genesis again until one scan completes
                                    with the node synced (an interrupted restore resumes this way; a restore made before the
                                    node had the chain completes at the first restart after it has synced, and getinfo's
                                    errors asks for that restart once the node has synced).
}

balance counts confirmed coins and this wallet's own unconfirmed outputs (a transaction whose every input
is this wallet's, such as change); unconfirmed_balance counts the other unconfirmed outputs (payments from
others). Post-quantum coins are transparent: balance = balance_ecc + balance_pq and
unconfirmed_balance = unconfirmed_balance_ecc + unconfirmed_balance_pq, by the same rule.

Examples:
> ycash-cli getwalletinfo 
> curl --user myusername --data-binary '{"jsonrpc": "1.0", "id":"curltest", "method": "getwalletinfo", "params": [] }' -H 'content-type: text/plain;' http://127.0.0.1:8832/
